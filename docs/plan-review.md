## 二、待决策 / 需先验证的问题（按优先级）

### P0 — 已作废（原 MiniMax 时间戳结论，引擎已换讯飞；存档备查）

> **2026-09-30 晚更新**：引擎换为讯飞超拟人后，下列 MiniMax 时间戳结论不再适用。新方案的验证点见下方「P0'」。原 MiniMax 结论（存档）：`t2a_v2` 带 `subtitle_enable:true` + `subtitle_type:"word"` 返回字/词级毫秒时间戳（`subtitle_file` 二次下载）；HTTP 单请求 1 万字符。若日后回退 MiniMax 可复用此结论。

### P0' — 新引擎（讯飞超拟人）待验证项
1. **口语化/语气词（最高优先）**：超拟人引擎可能自动加"嗯""就是说"等填充语；听书需书面语播报。x6 系列（含选定的聆玉菲/聆飞博）不支持 `oral` 参数，无法程序关闭。**spike 必试听**：若加语气词 → 改 x4 系列（子津/子阳）+ `remain=1`，或换非超拟人常规发音人。
2. **PCM 计时正确性**：用 `encoding=raw`、24kHz/16bit/单声道合成一句，验证「时长 = 字节数 ÷ 48000 秒」与实际播放时长一致（用播放器/ffprobe 对照）。
3. **句间 gap 听感**：句尾标点自带停顿 + 拼接静音（默认 150ms）是否自然，需试听调参。
4. **鉴权与并发**：`x-api-key`（APIPassword）简单鉴权可用性；免费额度（个人 1 万字符）够 spike；限流阈值实测。

**spike 内容更新**：拿讯飞免费额度跑 2~3 句，验证上述四点（发音人是否加语气词、PCM 计时、gap 听感、鉴权）。不再需要验证时间戳结构。

### P1 — 影响架构（2026-09-30 已定案）
3. **旧版本音频资产兼容 → 不做兼容（已定案）**：新版本不播放旧格式音频、不做迁移层；旧文件保留在磁盘但不入新库，用户用 PC 端重新合成导出。**文本导入与阅读不受影响。**
4. **无音频的书 → 可读不可听（已定案）**：保留 TXT/EPUB 纯文本导入与阅读，无音频章节照常阅读，仅「听书」提示「暂无音频（需 PC 端合成导入）」。
5. **注释音色与正文不同（已定案）**：PC 端正文用 `voice`、注释段用 `noteVoice`，两者必须不同。

### P2 — 实现细节，可后置
5. **注释段与正文段拼接**：两段不同批次/音色的音频拼在一个 mp3，跨段可能有响度跳变，需试听确认是否可接受。
6. **EPUB 注标丢失**：若源书注释标记是 EPUB 的 `<sup>` 上标而非字符，纯文本抽取会丢标记，`pairNotes` 就配不上。EPUB 解析需保留注标信息。
7. **`sourceHash` 严格校验可能误伤**：同一本书不同版本源文件 hash 不同，会误判"损坏"。建议降级为**警告不阻断**。
8. **大书体积/导入性能**：整章 mp3 一本 30 章可能 300MB–1GB，zip 后仍大；导入解压需后台线程 + 进度提示，避免卡 UI。
9. **工作量**：PC 端 5~7 天偏乐观（Wails 首搭 + 注释配对 + 断点续合 + 导出）。建议 spike 之后再给准数。

## 三、建议实施顺序

1. **Spike（0.5 天，改用讯飞免费额度）**：验证超拟人是否加语气词 + PCM 计时正确性 + 句间 gap 听感 + `x-api-key` 鉴权。
2. **抽共享解析模块（0.5 天）**：把 `splitSentences` / `isNoteParagraph` / 新增 `pairNotes()` 抽成手机与 PC 共用的纯 TS 模块，先写单测（含①②③、`[n]`、`*`、孤立注释、无标记等用例）。
3. **手机端瘦身 + 新播放器（阶段一）**：删合成/计费，加导入 + 句级播放 + 注释跳转。
4. **PC 端 MVP（阶段二）**：书籍导入 → 按章合成 → 导出 zip。
5. **联调发布（阶段三）**。
