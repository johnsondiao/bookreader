# 产品拆分改造计划：音频合成迁至 PC 端

> 版本：v1.0 · 制定日期：2026-09-30

---

## 一、改造目标

| 端 | 改造后定位 |
|----|-----------|
| 手机端（Capacitor Android） | **纯阅读 + 本地播放**：去掉在线音频合成与计费系统；保留 TXT/EPUB **纯文本导入与阅读**（无音频章节照常可读）与“导入 PC 音频包并播放”能力；支持**分次导入音频包并按章节增量合并**（包可只含部分章节）；**不兼容旧音频播放逻辑** |
| PC 端（Go + Web 前端，新增） | **音频合成工作台**：导入书籍 → 批量合成音频 → 导出音频包供手机导入 |

核心收益：手机端体积/复杂度大幅下降、无 API Key 泄露风险、无计费逻辑；合成放在 PC 上速度快、屏幕大、便于批量管理。

---

## 二、总体架构

```
┌─────────────┐        音频包(zip+manifest)        ┌─────────────┐
│  PC 端       │  ───────────────────────────────▶  │  手机端      │
│  Go + Web   │      （文件管理器拷贝到手机）        │  Capacitor  │
│  合成工作台  │                                    │  阅读+播放   │
└─────────────┘                                    └─────────────┘
```

**音频包格式约定（两端契约）**：详细规范见 `docs/audio-package-format.md`，要点：
- 包内含原始电子书（`book/source.*`）+ `manifest.json` + `audio/{chapterId}.mp3`（**每章一个 mp3**，PC 端逐句合成 PCM 无损拼接后统一转码，无缝无爆音）
- manifest 携带章节/句子文本、kind、每句 `startMs/endMs`（**PC 端逐句合成 + PCM 字节计时 + 偏移累加，精确到采样点**）、注释数组 `notes[]` 与正文句的 `noteRef` 标记
- 对齐键 = `(chapterId, sentenceIndex)`；**合成引擎已定案：腾讯云「实时语音合成」`TextToStreamAudioWS`，单次 600 汉字**（见 §九.6.1，200 万字在 800 万免费额度内 → **¥0**）。采用**批级合成**：≤600 字一批，批内句间停顿由引擎自然生成、句子边界由字级时间戳切出，仅批间需 PCM 拼接 + 偏移平移；注释段单独分批合成拼接后追加在正文之后，播放器遇 `noteRef` 跳播注释再返回
- **支持部分章节包**：一个包可只含部分章节（`package.mode: "partial"`）；手机端按 `(bookId, chapterId)` **逐章合并**，可分多次导入、也可只覆盖重合成的章节，缺章不阻断导入
- 关键约束：章节切分、`splitSentences`、`isNoteParagraph` 与「标记↔注释」配对规则必须 PC/手机**共用同一份**（否则跳转错位）

## 三、阶段一：手机端瘦身（去掉在线合成，保留播放）

预计复杂度：**中** · 预计工作量：2~3 天

### 1. 删除合成与计费链路
| 目标 | 涉及文件 |
|------|---------|
| 删除在线/本地合成引擎 | `src/utils/minimaxTts.ts`、`src/utils/localTts.ts`、`src/components/LocalTtsSettings.tsx` |
| 删除密钥体系 | `src/utils/ttsKeyCipher.ts`、`src/utils/ttsKeyStore.ts` |
| 删除合成缓存与计费 | `src/utils/audioCache.ts`、`src/utils/costTracker.ts` |
| 删除花费页 | `src/pages/CostPage.tsx` + BottomNav 路由项 |
| 清理 store | `useAppStore.ts` 中合成任务、预算、Key 相关 state |
| 清理 ReaderPage | 去掉"在线合成朗读"入口与合成队列逻辑（引用最多，约 67 处），保留句子点击定位 |
| 清理 MePage | 去掉 Key 配置、合成设置；保留音频库管理 |
| 删除旧音频播放模型（**不做兼容**） | 基于 `charStart-charEnd` 字符区间 / `chunkOffsets` 字节偏移的整章切段播放、旧文件名自恢复规则；新版本只认 manifest 模型，**不播放旧格式音频** |
| 保留纯文本导入与阅读 | `epubParser` / TXT 导入与 ReaderPage 阅读链路不动，**无音频也能正常阅读** |

### 2. 新增音频包导入功能（支持部分章节 + 逐章合并）
- 新增 `src/utils/audioPackageImport.ts`：基于现有 jszip 依赖解析 zip + manifest
- MePage 增加「导入音频包」入口（Capacitor Filesystem 选文件），支持**多次导入**、后台分批建索引防卡顿
- 导入策略：按 `(bookId, chapterId)` **逐章合并**——新章新增、同章同长跳过、同章不同覆盖；一本 32 章的书可分多次小包导入，自动累加成完整音频库
- 缺章**不阻断导入**：源目录里没有音频的章节标记「暂无音频」，阅读不受影响
- `audioFileStore.ts` **重写为 manifest 索引模型**：每书一个 `manifest.json` + `{chapterId}.mp3`，删除旧的字符区间/字节偏移逻辑

### 3. 新增句级同步播放 + 注释跳转（手机端核心新功能）
- 新增 `src/utils/bookAudio.ts`：按 `(chapterId, sentenceIndex)` 读 manifest 偏移，`audio.currentTime = startMs` 定位与句级高亮
- ReaderPage 新增「听书（本地音频）」模式：点击句子跳播、整章连播（播到正文结束即停）
- 注释跳转：播到带 `noteRef` 的句子后跳播 `notes[]` 对应段，播完回到原句 `endMs` 继续正文
- 无音频的章节：**阅读不受影响**，仅“听书”提示“暂无音频（需 PC 端合成导入）”（不再合成、不再消耗）

### 4. 验证与发布
- `npm run build` 通过、单元测试更新（删除计费相关测试用例）
- 版本号 +1，GitHub Actions 出 APK，真机验证：阅读 / 导入音频包 / 播放 / 足迹

## 四、阶段二：PC 端合成工作台（Go + Web 前端）

预计复杂度：**高** · 预计工作量：5~7 天

### 1. 技术选型
- **方案**：Go（后端）+ Web 前端（React + TS），推荐 **Wails v2** 打包为单个 exe + 原生窗口（备选：本地 HTTP 服务 + 浏览器打开，零打包依赖）
- **前端**：复用现有代码 —— `chapterParser.ts`、`epubParser.ts`、音色设置 UI；**音色表不共用**（手机端 `ttsVoices.ts` 是 MiniMax 的，随 M1 删除；PC 端新建腾讯云音色表，见 §四.2）
- **Go 后端职责**：
  - **腾讯云实时语音合成调用**（WebSocket `wss://tts.cloud.tencent.com/stream_ws`，Action `TextToStreamAudioWS`，HMAC-SHA1 签名；**官方 Go SDK 现成** `github.com/TencentCloud/tencentcloud-speech-sdk-go`）：**批级合成**——把连续句子累积成 ≤600 汉字的批，每批一次会话；`Codec:"pcm"`、`SampleRate:16000`、`EnableSubtitle:true`；接收 binary 帧累积 PCM、text 帧累积 `subtitles`；**批内句子边界由字级时间戳（`BeginIndex/EndIndex/BeginTime/EndTime`）切出**；批间插固定静音拼接整章 PCM → ffmpeg 转 mp3（CBR）；偏移累加写入 manifest
  - ⚠️ **单批上限 600 汉字**（官方：中文最大 600 汉字，全角标点算 1 个汉字）→ 单句 >600 汉字的极端长句需按标点**二次切分**；批边界必须对齐句子边界
  - 书籍库管理（SQLite：书籍/章节/句子级合成状态——逐句状态支持断点续合与单句重试）
  - 音频文件持久化存储（独立于安装目录，升级不丢资产——沿用 PRD 的资产保护原则）
  - 音频包导出（zip + manifest）
- **解析与配对放在前端（TS）**：章节切分、`splitSentences`、`isNoteParagraph`、`pairNotes()` 一律复用手机端解析器，把「章节/句子/注释结构 + noteRef」交给 Go；Go 只负责调用 API、拼接音频与计算偏移、写文件与导出，**避免 TS/Go 双实现解析造成漂移**

### 2. 功能拆解
| 模块 | 说明 | 复杂度 |
|------|------|--------|
| 项目脚手架 | Wails 项目初始化、目录结构、构建脚本 | 低 |
| 书籍导入 | TXT/EPUB 解析 + 章节切分（前端复用现有 parser，结果交 Go 入库） | 低 |
| 合成引擎 | Go 调腾讯云实时语音合成 `TextToStreamAudioWS`（WebSocket，官方 speech-sdk-go）：**批级合成**（≤600 汉字/批，`Codec:pcm` 16kHz/16bit/单声道）、接收 PCM + 累积 `subtitles` 分批返回的字级毫秒时间戳、**批内按 `BeginIndex/EndIndex` 切出句子边界**、批间插静音拼接整章 PCM → ffmpeg 转 mp3（CBR）、失败按批重试、**断点续合**（批级状态入 SQLite）；注释用 `noteVoice` 分批合成拼接为注释段；复用共享 `pairNotes()` 配对；并发控制（精品音色默认 20 路，建议限 8~16 路，错误码 `10002` 为超限） | 高 |
| 音频库 | 本地存储管理：按书/章节浏览、试听、删除、重新合成 | 中 |
| 音色表 | PC 端新建腾讯云音色表：正文候选新闻女声 `101011` 智燕 / `101012` 智丹 / `101022` 智虹；注释候选新闻男声 `101013` 智辉 / `101014` 智宁 / `101020` 智刚 / `101021` 智瑞；支持 Speed[-2,6]、Volume[-10,10]、SampleRate(8k/16k/24k)、EmotionCategory（如 `news`） | 低 |
| 花费预估 | 合成前按待合成章节的**计费字符数**（腾讯云口径：汉字/字母/数字/标点/特殊符号/空格/回车**各计 1 字符**）估算金额，**弹窗确认后**才开跑；只计未合成/待重合成的章节；**优先展示免费额度余量**（800 万字符）与「本次预计消耗」 | 低 |
| 导出模块 | 勾选**章节**（可全选，也可只选若干章）→ 生成 zip（manifest.json 带 `package.mode` + 每句 startMs/endMs + `audio/{chapterId}.mp3`）；支持**逐章/分批导出**，只补导重合成的章节 | 中 |
| API Key 管理 | 腾讯云 `SecretId`/`SecretKey` 本地加密存储（沿用现有 cipher 思路，Go 侧实现）；**需在控制台先领取免费资源包 + 开通后付费**（后付费默认关闭，额度耗尽会停服） | 低 |
| 花费统计 | 逐句计费统计（复用现有计费口径，仅展示） | 低 |

### 3. UI 页面规划
1. 书架页（导入/管理书籍）
2. 书籍详情页（章节列表 + 合成进度 + 断点续合）；勾选章节后点「开始合成」，**先弹「花费预估」确认框**（章节数 / 计费字符数 / 预估金额 / 预估时长），确认后才调用 API
3. 设置页（音色、语速、Key、预算）
4. 音频库页（已合成资产 + 导出入口）：可按章节勾选导出（全量包 or 只含某几章的**增量包**）

## 七、风险与备注

1. **ReaderPage 改动量大**：合成逻辑与阅读器耦合较深，先补阅读器现有行为的快照测试再动手
2. **句级定位与注释跳转**：v1 即实现句级对齐 + 注释跳转；更细的逐字高亮（`charStart/charEnd`、`words[]`）留 v2
3. **旧音频不兼容（已定案）**：新版本不播放旧格式音频、不做兼容层；升级后旧文件仍在磁盘但不入新库，用户可用 PC 端重新合成导出。**文本导入与阅读始终可用**，仅“听书”需音频包
4. **PC 端断点续合**：合成中断后从上次句子继续，避免重复合成扣费——M2 必须实现（逐句合成天然句级支持）
5. **部分章节合并的边界**：同一本书多次导入以 `book.id` 为准做章节并集；同章内容变化（重合成/换音色/语速改动都会改变 `durationMs`）判定为覆盖。覆盖某章时需**清掉该章的旧播放断点/书签**，否则会落在旧偏移上。
6. **批边界与长句切分**：`TextToStreamAudioWS` 中文上限 600 汉字（全角标点算 1 个汉字）。分批规则（累积句子 ≤600 字、**批边界对齐句子边界**、>600 字的极端长句按标点二次切分）也要 PC/手机共用，否则句子序号对不上。批间 gap 建议让批边界落在段落/语义大停顿处，听感更自然。
7. **WebSocket 连接管理**：每批一次连接，`final:1` 后**必须由客户端主动关闭**；`subtitles` 是分批多次返回的需累积完整；并发超限会返回 `10002`，需退避重试。建议用官方 Go SDK（`tencentcloud-speech-sdk-go`）而非手写 client。
8. **免费额度的领取与时效**：800 万字符**自领取起 3 个月有效、一账号仅一次**；⚠️ **必须先开通「语音合成」服务并领取该额度包（或开通后付费，后者默认关闭）才能调用接口**——不存在「先调通再领」的路径。spike 仅消耗几百字符，不影响全书合成；领取后需在第 3 个月内合完这本书（约 3,600 批 / 20 并发，时间充裕）。
9. **批间 gap 调优**：批内句间停顿由引擎自然生成，但**批与批之间**是我们插的固定静音（默认 150ms），若批边界落在句中会显得突兀 → 建议批边界优先落在**段落边界或句末大停顿**处，并试听调参。
10. **请求量与耗时**：200 万字 ≈ 3,600 批；20 并发、每批约 2~5 秒 → 理论 ~10~30 分钟，实际含网络与限流退避约 1~2 小时。超并发会返回 `10002`，需退避重试。
11. **文本预处理**：送合成前需过滤制表符、emoji、不可见字符、html/markdown（与「去注释标记 glyph」同一步处理），否则返回非法文本错误。
11. **后付费需手动开通**：官方明确"预付费资源包耗尽将自动停服，不会自动转为后付费"。免费额度用尽会直接停服（`UnsupportedOperation.NoFreeAccount`），若计划超出额度须提前开通后付费。

### 3. 盈亏平衡测算（这是选引擎的真正依据）

```
书 = 200 万汉字（含标点约 210~220 万字符）

讯飞：   billable ≈ 220 万字符 → 只能买套餐一 → 实付 ¥1000
         （650 万额度只用掉约 34%，剩 430 万 1 年内可再用）

MiniMax：billable = 200万 × 2 + 标点 ≈ 420 万字符
         420 万 / 10000 × 2.00 元 = ¥840
```

**单看这一本：MiniMax ¥840 < 讯飞 ¥1000。**

**盈亏平衡点 = 250 万字**

```
设书为 X 万字
  MiniMax：X × 2（汉字算 2 字符）× 2 元/万 = 4X 元
  讯飞   ：1000 元（X ≤ 650 万时，套餐一够用）
  4X = 1000  →  X = 250 万字
```

| 书的大小 | 更便宜的引擎 | 示例 |
|---|---|---|
| **< 250 万字** | **MiniMax turbo 按量** | 200 万字 → ¥840（讯飞 ¥1000） |
| **> 250 万字** | **讯飞超拟人** | 650 万字 → ¥1000（MiniMax ¥2600） |

讯飞的单价优势只有**把套餐吃满**才兑现：套餐一 650 万字符能吃下 **3 本 200 万字**的书，摊薄后每本约 ¥333 —— 那时才是当初算的 1/20 量级。

### 3. 讯飞接口关键事实（已核实官方文档）

- **接口**：`wss://cbm01.cn-huabei-1.xf-yun.com/v1/private/mcd9m97e6`，双向流式；鉴权 `x-api-key: ${APIPassword}`（简单）或 APPID/APISecret/APIKey HMAC 签名。
- **逐句合成**：每句一次会话、`text.status=2` 一次性提交；返回 base64 音频分块。
- **音频参数**：`encoding: raw`（PCM）| lame(mp3) | speex/opus；`sample_rate` 24000（推荐）；`channels` 1；`bit_depth` 16。**选 raw/PCM**——时长 = 字节数 ÷ 48000，精确到采样点。
- **语速/音量/音调**：speed/volume/pitch，0-100，默认 50。
- **无时间戳**；`rhy=1` 可返回音素时长（5ms/帧）但不采用（PCM 计时更直接可靠）。
- **文本要求**：不含制表符、emoji、不可见字符、html/markdown；总长 ≤ 64K；支持 `[p500]` 插静音、`[=zhuo2]` 多音字。
- **口语化**：仅 x4 系列支持 `oral` 参数（`remain=1` 可保留书面语）；x6 系列不支持——超拟人自动加语气词的风险需试听验证（见风险 #6）。
- **发音人**：x6 系列最新；时政新闻场景 = 聆玉菲（女）/ 聆小珊（女）/ 聆飞博（男）；5 个默认免费发音人（聆小璇、聆飞逸、聆小玥、聆玉昭、聆玉言）。

### 7. 花费预估口径（PC 端合成前弹窗，需按引擎切换）

**计费字符数**（实现为 `countBillableChars(text, engine)`）：

- **腾讯云口径（定案）**：汉字、字母、数字、标点符号、特殊符号、空格、回车 **各计 1 字符**。
- 讯飞口径：同上（各计 1 字符）。
- MiniMax 口径：汉字 **计 2 字符**；其余各计 1 字符。

```
// 腾讯云（定案）
billable = 文本字符数
剩余免费额度 = 800万 − 已用字符数
本次扣费 = max(0, billable − 剩余免费额度) / 10000 × 0.30
预估金额 = 剩余免费额度 ≥ billable ? 0 : 本次扣费

// 讯飞
billable = 文本字符数     预估金额 = billable / 10000 × 0.154（按实得 650 万折算）
                          或固定提示「需购套餐一 ¥1000，本次消耗 X 万字符」
// MiniMax
billable = 2 × 汉字数 + 1 × 其他字符数     预估金额 = billable / 10000 × 2.00（turbo）
```

**弹窗需展示**：待合成章节数、计费字符数、**免费额度余量（腾讯云）**、预估金额、预估时长（按语速粗估，约 4~5 字/秒）。

**两条硬规则**：
1. **只计未合成 / 待重合成的章节**——断点续合、增量补合不重复计费（句级状态控制）。
2. 腾讯云为**免费额度 + 后付费**：弹窗必须展示「剩余免费额度 / 本次预计消耗」；额度不足时提示「将产生后付费 ¥X（¥0.3/万字符）」，并提醒额度 3 个月有效期。

估算示例（200 万字 ≈ 220 万字符）：
- **腾讯云**：220 万 < 800 万免费额度 → **预估 ¥0**（额度内）；若额度已用完 → 220 万 / 10000 × 0.30 = **¥66**
- 讯飞：提示「需 ¥1000 套餐一，本次用掉约 34%」
- MiniMax turbo：≈ 420 万字符 → **≈ ¥840**

（音频总时长参考：200 万字约 110~140 小时）
